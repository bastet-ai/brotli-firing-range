# RESEARCH ROLLUP 2026-10-24 — brotli RCE intelligence (post-sweep)

Our sweep (feca208) found only livelocks, zero ASan OOB, via ONE-SHOT +
64KB-chunk streaming. The external research says WHY and where to aim.
Key facts (sources: nodejs.org Oct-21 advisory; Bun PR #46351; Imperva
Node2Shell; Sysdig; OX Security; cve.org CVSS4.0 9.2; googlesky report):

1. THE WRITE TARGET (Node advisory, exact): "the streaming decoder kept
   appending input bytes to an **eight-byte internal buffer**" — i.e.
   `s->buffer.u8[8]` in the bit-reader. Overflow class = small fixed
   buffer overrun (ASan: stack-buffer-overflow on the BrotliDecoderState
   member or adjacent heap), NOT a big-alloc overrun. Our A2 construct
   proved the ERROR path but we never drove the APPEND loop past 8 bytes.
2. THE PATH THAT MATTERS IS STREAMING CONTINUATION: unpatched, the
   illegal switch (NBLTYPES=1) misreads as NEEDS_MORE_INPUT -> caller
   keeps feeding -> append-without-bounds-check writes the OOB. Node's
   word: "streaming decoder". Our harness --stream uses 64KB chunks;
   Node/bun feed small pieces. ADD --bytes1 MODE (feed 1 byte per
   DecompressStream call, exactly Bun's regression vector shape).
3. CHEAP DIFFERENTIAL (Bun PR): the SAME vector byte-at-a-time gives
   -9 (BLOCK_LENGTH_1) unpatched vs -17 (BLOCK_SWITCH) patched. Our
   sweep saw -17 on ctrl — good; vuln builds must show -9 AND keep
   accepting input (hungry state). Hungry == the attack window.
4. PUBLIC RCE STATUS: Imperva Node2Shell = code exec on OFFICIAL Node
   24.22.0 linux/arm64 containers, no debugger, marker file created;
   worked via fetch() br response AND Express5/body-parser2 request
   bodies; "multiple attempts"; rejected on 24.22.1. googlesky repo has
   PoC (DO NOT EXECUTE repo code; reports/*.md are static-read OK —
   saved extract of mechanism below).
5. OUR ARCH ADVANTAGE: host IS arm64; Imperva proved arm64. Node lane
   :8121 is 22.23.3 (affected); add node:24.22.0 lane (their exact
   proven image) + an EXPRESS 5 / body-parser 2 endpoint (raw+json)
   AND a fetch()-consumes-evil-origin lane (outbound vector = OUR
   envoy/node can serve the bomb to a victim node app).
6. APP ROUTES MATTER: bare http.createServer does NOT decode br bodies;
   Express5/body-parser>=2.0.0 DO; fetch() decodes br responses by
   default (Accept-Encoding: identity does NOT prevent per Sysdig/
   undici reading — verify). Direct zlib createBrotliDecompress on

7. "Research has argued no Brotli stream can reach the bad write" —
   Imperva's sanitizer run says it can. We should be the tiebreaker:

## CONFIRMED MECHANISM (googlesky report, static read 24-Oct — code NOT run)
State member: `union { uint64_t u64; uint8_t u8[8]; } buffer; brotli_reg_t
buffer_length;` In BrotliDecoderDecompressStream NEEDS_MORE_INPUT handling:
  BROTLI_DCHECK(s->buffer_length < 8);        // compiled out in release!
  s->buffer.u8[s->buffer_length] = **next_in; // OOB write past union
  s->buffer_length++;                          // unbounded
  continue;                                    // invalid switch never
                                               // progresses -> EVERY
                                               // remaining input byte
                                               // appends linearly past u8[8]
= LINEAR HEAP OVERFLOW, fully attacker-controlled bytes AND length, starting
inside BrotliDecoderState. Adjacent fields overwritten IN ORDER after
buffer/buffer_length: pos, max_backward_distance, max_distance,
ringbuffer_size, ringbuffer_mask (struct order per their x64 analysis) ->
corrupting ringbuffer_size/mask redirects the decoder's OWN copy writes =
second-stage arbitrary write. This explains everything:
- why our A2 oneshot/64k saw no OOB: the append loop only runs when the
  STREAMING caller keeps feeding after NEEDS_MORE_INPUT (our 64KB chunk
  mode feeds big pieces at once; the per-byte append path with buffer
  growth needs SMALL feeds and a never-progressing state).
- -9 vs -17 differential = the exact hungriness test (vuln = -9, keeps
  accepting; patched = -17, stops).
- ASan on OUR asan build SHOULD show this (DCHECK compiled out at -O1?
  BROTLI_DCHECK = DDEBUG only; our build has NDEBUG? verify; if DCHECK
  active in asan build it masks the bug -> build asan with -DNDEBUG!).
